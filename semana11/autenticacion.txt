1. ¿Qué es el login en una aplicación?
El login (o inicio de sesión) es la puerta de entrada de una aplicación. Su función principal es la autenticación, que consiste en identificar a un usuario mediante credenciales (como correo y contraseña) antes de darle acceso a ciertas funciones del sistema. 
En una plataforma comunitaria, el login no es solo un trámite visual; actúa como una barrera necesaria para organizar la confianza. Al saber exactamente quién está ingresando, el sistema puede asignar un rol específico (por ejemplo: ciudadano, revisor o administrador). Esto asegura que cada persona interactúe únicamente con lo que le corresponde, otorgando control y trazabilidad a los procesos. 
2. ¿Por qué algunas rutas deben estar protegidas?
En el desarrollo web, las rutas se dividen en públicas (accesibles para cualquiera, como la pantalla de inicio o el formulario de registro) y protegidas (restringidas). 
Las rutas deben estar protegidas porque contienen información privada, registros internos o permiten realizar acciones críticas (como modificar datos o cambiar estados) que no deben estar disponibles para todo el mundo. 
Para protegerlas se utiliza un middleware de autenticación. Este componente técnico funciona como un vigilante en la puerta : cuando un usuario intenta entrar a una ruta protegida (como el panel de control o dashboard), el middleware intercepta la petición, verifica si existe un token de acceso válido y, si la validación falla, deniega el acceso inmediatamente para evitar intromisiones o suplantaciones. 
3. ¿Qué tipo de información NO debería exponerse públicamente?
Bajo los principios de privacidad por diseño y normativas legales como la Ley 1581 de protección de datos personales, existen datos que jamás deben ser visibles ni circular abiertamente: 
•	Secretos del sistema y desarrollo: Contraseñas en texto plano, tokens de seguridad, archivos de configuración entorno (.env) y claves de interfaz de programación (API Keys). Si estos datos se suben por error a repositorios públicos como GitHub, toda la infraestructura de la aplicación queda vulnerable. 
•	Datos personales y sensibles de la ciudadanía: Nombres completos vinculados a números de identificación (cédulas), teléfonos, correos electrónicos, direcciones residenciales o datos de seguimiento privado. 
•	Información en flujos automatizados: Cuando se integra el sistema con herramientas externas (como N8N, Google Sheets o Telegram), los prompts de inteligencia artificial o los mensajes de alerta deben estructurarse de tal forma que se excluyan los datos reales del ciudadano. Los datos sensibles deben ser insertados por el servidor únicamente en el documento final privado, evitando transferencias inseguras.
